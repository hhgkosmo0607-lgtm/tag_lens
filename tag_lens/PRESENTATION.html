기술 스택 — 사전학습 모델

모델을 처음부터 학습시키는 대신, 이미 잘 훈련된 모델에게 어떤 질문을 던질지, 그 답을 얼마나 믿을지를 정교하게 설계하는 방식을 택했습니다.

분류 — CLIP

clip-vit-base-patch32
장르 · 동물 · 주야간 · 실내외 판별을 전부 제로샷으로 처리

Transformer 비전 트랜스포머(ViT) + 텍스트 트랜스포머 — 사진+문장 약 4억 쌍으로 학습

검출 — mediapipe

BlazeFace(얼굴), EfficientDet-Lite0(동물 크기) — 구글 CNN 사전학습 모델을 사용

CNN BlazeFace는 MobileNet 계열, EfficientDet-Lite0은 EfficientNet+BiFPN — COCO 등으로 학습

임베딩 — MobileNetV2

ImageNet 사전학습, 1280차원 벡터로 유사 사진 검색

CNN 역전된 잔차 구조(inverted residual) — ImageNet 1000-class로 학습

CLIP만 트랜스포머이고 나머지 둘은 전부 CNN입니다. CNN 쪽은 정해진 라벨로 학습된 걸 파인튜닝 없이 그대로 쓰고, CLIP만 사진+문장 쌍으로 학습돼서 프롬프트로 기준을 바꿀 수 있습니다.

얼굴 찾기 — 이중 확인

mediapipe는 구글의 얼굴 찾기 AI입니다. 카메라 앱을 켜면 얼굴에 네모 박스가 자동으로 뜨는 것과 같은 원리입니다. 혼자서는 벽에 붙은 화재경보기 벨(둥글고 좌우대칭인 모양)을 얼굴로 착각했고, 심지어 진짜 얼굴보다 더 자신 있게 틀렸습니다.

잠깐 — CLIP이란?

사진 한 장과 문장 여러 개를 주면 "어느 문장이 제일 잘 어울려?"를 점수로 알려주는 AI입니다. 인터넷의 수억 장 "사진+설명" 쌍을 이미 보고 배운 상태라, 새로 가르칠 필요 없이 물어보는 문장(프롬프트)만 바꾸면 됩니다 — 이걸 제로샷(zero-shot)이라 부릅니다.

원래는 CNN(우리가 직접 사진을 모아 학습시키는 방식)을 썼습니다. 비유하면 CNN은 정해진 문제집만 외운 학생, CLIP은 인터넷을 통째로 읽은 사람에게 말로 물어보는 것과 같습니다.

CNN → CLIP 교체 근거

장르CNN "자연" 98.6% 오판CLIP 정답 65~81%
실내외검증 97% → 실전 13.3%73.3%로 향상
낮/밤실패 5장 중 5장 오판5장 중 4장 정답
동물ImageNet 품종 편향 심함4중 안전장치로 보정

CNN은 준비한 학습 데이터 범위 안에서만 똑똑합니다. CLIP도 만능은 아니라서, 확신도 낮으면 "기타"로 보내는 안전장치를 항상 같이 둡니다.

장르 분류 — 여섯 문장 중 고르기

얼굴이 검출되면 바로 "인물"로 확정합니다. 없으면 CLIP에게 '자연/도시/음식/사물/인물' 다섯 문장을 주고 가장 잘 맞는 걸 고르게 합니다. 확신도가 60% 미만이면 억지로 고르지 않고 "기타"로 보냅니다.

실제로 60% 미만인 사진들을 보면, 사람이 봐도 "자연인지 도시인지" 헷갈리는 경계선상 사진이 대부분이었습니다 — AI만 헷갈리는 게 아니라 애초에 정답이 하나로 안 떨어지는 사진인 겁니다.

"인물" 문장 하나만으론 역광 시장·행사 군중 사진을 못 잡아서(전체로 보면 "음식" 82%로 오판), "군중" 문장을 추가해 점수를 합산했습니다.

"CLIP이 강아지/고양이/말/기타동물 중 하나이거나, 동물이 아니라고 판단한다"가 기본 동작입니다. 하지만 이 프로젝트에서 안전장치가 가장 두꺼운 곳이기도 합니다 — CLIP 판단 하나만 쓰면 오판이 많아서, 각 단계는 "이전 단계를 통과한 새로운 오탐"을 막기 위해 순서대로 4겹을 추가했습니다.

STEP 05 · 되돌리기
ai/genre_predict.py — resolve_genre_with_animal

장르 재확인

동물이 감지됐는데 사람 얼굴이 없으면 장르를 다시 "기타"로 되돌립니다. 장르 판단 AI는 "사람 얼굴 클로즈업"을 많이 배운 감각이 있어서, 고양이 얼굴 클로즈업을 사람으로 착각한 적이 있습니다(96.6% 확신으로 "인물" 오판).

face_count == 0 조건이 핵심 — 진짜 사람 얼굴이 같이 찍혔다면(반려동물과 함께 찍힌 사진처럼) "인물" 판정은 근거가 있으니 되돌리지 않습니다.

ai/genre_predict.py 
def resolve_genre_with_animal(
    genre: str,
    animal: str | None,
    face_count: int
) -> str:
    if (
        genre != "기타"
        and face_count == 0
        and animal is not None
    ):
        return "기타"
    return genre
STEP 06 · EXIF 우선
ai/daynight_predict.py

낮/밤 판별

EXIF는 사진 파일 안에 눈에 안 보이게 저장되는 정보입니다 — 촬영 시각, 카메라 기종 등이 들어있습니다. 사진이 밝은지 AI가 추측하는 것보다, 이미 기록된 촬영 시각을 읽는 게 훨씬 정확합니다.

EXIF 파싱의 함정 — 숨겨진 SubIFD

카메라 시계 오류 보정 & 폐기된 3중 다수결

카메라가 시간대를 모를 때 남기는 기본값(+00:00)과 실제 시간대가 같이 있으면, 그 차이만큼 자동 보정합니다.

처음엔 EXIF + CLIP + 밝기 3중 다수결을 시도했다가 되돌렸습니다. 그림자 짙은 대낮 숲 사진 250장 중 47%에서 두 픽셀 기반 신호가 동시에 오판해, 다수결이 정확한 EXIF를 2:1로 뒤집었습니다.

교차검증은 서로 독립적인 방법끼리 해야 의미가 있다는 걸 이때 배웠습니다.

    if is_bw:
        tags.add("#흑백")
    elif color_tone is not None:
        tags.add(f"#{color_tone}")

    if indoor == "실내":
        tags.add("#실내")
    if animal is not None:
        tags.add(f"#{animal}")

    return sorted(tags)
Product

UI/UX & 검증 방식

갤러리 필터(태그 AND/OR, 별점, 날짜)는 선택 즉시 반영됩니다.

라이트룸 스타일 별점 토글, MobileNetV2 임베딩 기반 유사 사진 검색 TOP 10을 제공합니다.

하지만 진짜 중요했던 건 UI가 아니라 검증 방식이었습니다.

82장
실사용 테스트 사진

자동화된 스크립트 검증도 했지만, 대부분의 버그는 직접 서버를 띄우고 실제 사진을 하나씩 업로드하며 발견했습니다. 테스트 데이터로는 못 잡는 '실제 사진'과 '테스트용 사진'의 차이에서 나온 문제들이었습니다.

재학습 없이 정확도를 올리는 방법은 결국 이 82장 전수 테스트였습니다 — 오분류를 하나씩 찾아 프롬프트 문장을 다듬거나, 임계값/gap 같은 후처리 기준으로 보완하는 반복이었습니다.

Self-review

부족한 점 및 개선 가능한 점

발표를 준비하며 코드를 다시 훑어보다 스스로 찾은 아쉬운 지점입니다. 지금 서비스가 망가지는 수준은 아니지만, 더 잘할 수 있었던 부분들입니다.

01

CNN 학습 전처리 미비

센터크롭 없이 원본 비율을 무시하고 리사이즈(찌그러짐) + ImageNet 정규화(preprocess_input, -1~1) 대신 단순 rescale=1./255 사용

같은 프로젝트의 ai/embedding.py는 정규화를 정확히 맞게 썼는데, 분류기 학습 쪽에서만 놓침 — CNN 낮은 정확도는 방식 한계만이 아니라 구현 실수도 섞여있었음
02

중복 업로드 검사 순서가 비효율적

얼굴·장르·동물·낮밤·실내외 AI 추론 5번을 전부 끝낸 뒤에야 해시로 중복을 확인함

중복 검사는 이미지 로드 직후 계산 가능한 해시 하나면 충분 — 순서만 옮기면 간단히 고쳐지는 낭비
03

Average Hash가 완전 일치만 검사

find_duplicate_by_hash()가 해시 정확 일치만 확인 — 해밍 거리 비교가 원래 목적에 더 맞음

살짝 재인코딩된 같은 사진은 중복으로 못 잡을 수 있음
04

장르 CLIP 실패 시 안전장치 건너뜀

predict_genre()의 예외 처리 경로가 '확신도 60% 미만 → 기타' 안전장치를 건너뛰고 바로 반환

indoor_predict.py는 같은 상황에서 안전장치를 제대로 통과시킴 — 대조해보면 놓친 부분이 분명함
05

실서비스 확장에는 최적화가 더 필요함

현재는 로컬 Flask 개발 서버 기준. CLIP+mediapipe+MobileNetV2를 합치면 메모리 약 3GB, GPU 가속 없이 CPU로만 동작

실서비스로 키우려면 모델 경량화(양자화, GPU 가속, 배치 처리) 작업이 필요함

정리하면 이 다섯 가지는 '고장'이 아니라 '더 다듬을 수 있는 지점'입니다.

Takeaways

마무리

01

AI 하나만 그대로 믿지 않는다

AI는 늘 '그나마 그럴듯한 답'을 1등으로 뽑는 성질이 있어서, 확신 점수·점수 차이·크기 같은 서로 다른 확인 방법을 겹쳐서 검증했습니다.

02

교차검증 방법은 서로 독립적이어야 한다

비슷한 방식끼리 다수결을 하면 오히려 맞는 답을 틀린 답이 이길 수 있다는 걸 실측으로 확인했습니다.

03

버그는 실제로 써봐야 나온다

오늘 보여드린 안전장치는 전부 검증 스크립트가 아니라, 실제 사진을 업로드하며 발견한 것들입니다.

감사합니다. 질문 받겠습니다.
