STEP 01 · AI 이전

이미지 로드 & 전처리

사진 파일을 열어서 컴퓨터가 처리할 수 있는 숫자 격자(픽셀) — 즉 NumPy 배열 — 로 바꿉니다. OpenCV(cv2.imread)로 열면 색상 채널 순서가 흔히 쓰는 RGB가 아니라 BGR로 읽힙니다. 그래서 CLIP이나 mediapipe에 넘기기 직전에 항상 RGB로 다시 바꿔줍니다.

스마트폰 세로 사진에는 재밌는 함정이 있습니다. 카메라 센서는 늘 가로 방향으로 픽셀을 기록하고, "90도 돌려서 보여줘라"는 지시만 EXIF의 Orientation 태그에 따로 저장합니다. 찍자마자 픽셀 전체를 회전시키는 건 느리고 비효율적이기 때문입니다. 이 태그를 무시하는 프로그램으로 열면 사진이 옆으로 눕거나 거꾸로 보입니다.

다행히 OpenCV의 cv2.imread()는 3.2 버전부터 이 EXIF Orientation을 기본으로 자동 적용해서 픽셀을 올바른 방향으로 돌려줍니다. 그래서 이 프로젝트에서 회전을 위한 코드를 따로 작성하지는 않았습니다. 다만 회전이 안 맞으면 뒤에 나오는 얼굴 검출(mediapipe)이 누운 얼굴을 잘 못 잡아서, 파이프라인 전체가 틀어집니다. 아직 AI가 등장하기 전, 순수 이미지 처리 단계입니다.

STEP 02 · mediapipe + CLIP

얼굴 찾기 — 이중 확인

mediapipe는 구글의 얼굴 찾기 AI입니다. 이 프로젝트는 그중에서도 5m 이내 멀리 있는 얼굴, 작은 얼굴까지 잡는 'full-range' 모델을 씁니다 — 2m 이내 정면 위주만 보는 'short-range' 모델보다 놓치는 얼굴이 적습니다.

문제는 재현율을 높이려다 보니 오탐도 늘어난다는 점입니다. 노을 진 구름을 신뢰도 0.53~0.54로 얼굴이라 착각한 데 이어, 벽에 붙은 사진 콜라주 속 자판기 버튼 패널(둥글고 좌우대칭인 격자 무늬)을 신뢰도 0.642로 얼굴로 잡은 사례가 실제로 있었습니다 — 심지어 진짜 얼굴보다 더 자신 있게 틀린 겁니다.

실측해보니 이 오탐(0.642)과 가장 가까운 진짜 얼굴(0.656) 사이 차이가 겨우 0.014였습니다. 그래서 그 중간인 0.65를 기준선으로 잡았습니다.

기준선 하나만으로는 부족해서, 찾아낸 얼굴 박스에 위아래·좌우로 60% 여백을 두고 잘라낸 뒤(너무 딱 맞게 자르면 머리카락이나 목 같은 맥락이 사라져서 CLIP도 판단하기 어려워집니다) CLIP에게 "진짜 사람 얼굴 클로즈업이냐, 아니면 얼굴처럼 생긴 원형 물체·표지판·버튼이냐"를 다시 물어봅니다. 진짜 얼굴 10건은 전부 0.270 이상, 오탐은 0.049로 확실하게 갈렸습니다.

덤으로 이 2차 검증은 뜻밖의 효과도 있었습니다 — 배경에 너무 작게 찍혀서 잘라내도 얼굴처럼 안 보이는 행인의 얼굴(신뢰도 0.031)까지 같이 걸러줘서, 사진의 진짜 주제가 아닌 배경 인물 때문에 장르 전체가 '인물'로 강제되는 문제도 같이 완화됩니다.

잠깐 — CLIP이란?

사진 한 장과 문장 여러 개를 주면 "어느 문장이 제일 잘 어울려?"를 점수로 알려주는 AI입니다. 인터넷의 수억 장 "사진+설명" 쌍을 이미 보고 배운 상태라, 새로 가르칠 필요 없이 물어보는 문장(프롬프트)만 바꾸면 됩니다 — 이걸 제로샷(zero-shot)이라 부릅니다.

원래는 CNN(우리가 직접 사진을 모아 학습시키는 방식)을 썼습니다. 비유하면 CNN은 정해진 문제집만 외운 학생, CLIP은 인터넷을 통째로 읽은 사람에게 말로 물어보는 것과 같습니다.

CNN은 준비한 학습 데이터 범위 안에서만 똑똑합니다. CLIP도 만능은 아니라서, 확신도 낮으면 "기타"로 보내는 안전장치를 항상 같이 둡니다.

장르 분류 — 여섯 문장 중 고르기

얼굴이 검출되면 바로 "인물"로 확정합니다. 없으면 CLIP에게 '자연/도시/음식/사물/인물' 다섯 문장을 주고 가장 잘 맞는 걸 고르게 합니다. 확신도가 60% 미만이면 억지로 고르지 않고 "기타"로 보냅니다.

실제로 60% 미만인 사진들을 보면, 사람이 봐도 "자연인지 도시인지" 헷갈리는 경계선상 사진이 대부분이었습니다 — AI만 헷갈리는 게 아니라 애초에 정답이 하나로 안 떨어지는 사진인 겁니다.

"인물" 문장 하나만으론 역광 시장·행사 군중 사진을 못 잡았습니다. 줄 서있는 사람들과 조명 켜진 부스가 있는 야시장 스타일 구도였는데, 전체로 보면 "음식" 82.1%로 오판했습니다. 그런데 군중 부분과 부스 부분을 따로 잘라 테스트해보니 각각 "인물" 44.2%, "인물" 64.3%로 오히려 인물 쪽이 우세했습니다 — 특정 피사체가 아니라 "역광 군중 + 조명 켜진 부스"라는 전체 구도 자체가 노점상·야시장 음식 사진 스타일과 겹친 겁니다. 그래서 "군중" 문장을 추가해 점수를 합산했습니다.

그런데 군중 문장을 추가하고 나니 새 부작용이 생겼습니다. 82장을 재분류하다가, 같은 얼굴 그림(모나리자)이 여러 장 반복 인쇄된 포스터 매대 사진이 이 "군중" 문장에 낚여서 "기타"였던 게 "인물"로 잘못 바뀐 걸 발견했습니다 — 사람 얼굴이 격자로 반복된 패턴을 CLIP이 진짜 군중으로 착각한 겁니다. 그래서 "인쇄물이 반복 진열된 사진"이라는 거부권 문장을 하나 더 추가했습니다. 이 문장의 점수가 인물·군중 점수보다 높으면 군중 보너스만 취소하고, 순수 "인물" 문장 점수만 남깁니다.

동물 판별

기본 동작은 간단합니다 — CLIP이 사진을 보고 강아지·고양이·말·기타동물 중 하나이거나, 동물이 아니라고 판단합니다. 다만 이 프로젝트에서 안전장치가 가장 두꺼운 곳이기도 합니다. CLIP 판단 하나만 믿으면 오판이 많아서, "이전 단계를 통과하고도 여전히 틀리는 새 사례"가 나올 때마다 안전장치를 하나씩 추가했고, 지금은 4겹이 됐습니다.

01

상대 비교 — 동물 vs 비동물

CLIP에게 강아지·고양이·말·새·야생동물 같은 "동물 문장"들과 식물·사물 같은 "비동물 문장"들을 같이 주고, softmax로 "동물 쪽 합계가 비동물 쪽보다 높은가"를 비교합니다. 이것만으로는 부족했습니다 — 배경에 작은 동물 그림이 있는 커피잔 사진이 "새"로 96% 확신도로 오탐됐습니다. 사실 이 사진은 어떤 문장과도 강하게 안 맞았는데, 상대 비교만 하다 보니 "그나마 덜 안 맞는" 후보가 부풀려진 겁니다.

근거: 약한 신호끼리 비교해도 상대적으로 1등은 반드시 나옴
02

최소 확신 점수 — 23.0

1번 게이트의 허점을 막기 위해, softmax를 거치기 전 원본 유사도 점수(로짓) 자체가 23.0 이상이어야 한다는 절대 기준을 추가했습니다. "상대적으로 1등"이 아니라 "절대적으로도 충분히 강한 신호"인지 따로 확인하는 겁니다.

근거: 정탐 최고 점수 24~28점대 / 방금 같은 오탐은 아무리 높아도 21점 이하
03

1등-2등 점수 차이 — 2.5

그래도 캄캄한 밤 풍경 반사 사진이 24.99점으로 2번 게이트마저 통과해버렸습니다. 진짜 동물 사진은 1등 종 점수가 2등보다 확실히 높게 튀는데, 이런 오탐은 개·고양이·말·새 점수가 서로 비슷비슷하게 붙어있었습니다. 그래서 1등과 2등 종의 점수 차이가 충분히 벌어져야 한다는 세 번째 기준을 추가했습니다.

근거: 정탐 차이 3.68~5.68점 / 오탐(야경 반사 등) 차이 0.80~1.56점
04

화면 대비 크기 게이트 — 1%

마지막으로, 노을 사진 속에 점 하나만 한 크기로 찍힌 새까지 태그가 붙는 게 과했습니다. CLIP은 사진 전체의 유사도만 볼 뿐 크기 개념이 없기 때문입니다. 사진을 축소해서 확신도가 떨어지는지 먼저 시도해봤지만 실패했습니다 — 축소에 대한 강건성이 크기와 무관했고, 오히려 확실한 승마 사진이 32px로 축소되니 확신도가 폭락했습니다. 그래서 mediapipe Object Detector로 실제 바운딩박스 면적을 재서, 화면의 1% 미만이면 태그를 안 붙이도록 했습니다.

근거: 점만 한 새는 최대 0.047% vs 확실한 동물은 4.4% 이상 (165배 격차)

        # 동물 문장 5개 + 비동물 문장 2개, CLIP에 한 번에 질의
        prompts = _SPECIES_PROMPTS + _NON_ANIMAL_PROMPTS
        inputs = processor(text=prompts, images=pil_image,
                            return_tensors="pt", padding=True)
        with torch.no_grad():
            logits = model(**inputs).logits_per_image[0]
            scores = logits.softmax(dim=0)   # ← 게이트 ① 계산용 확률

        species_logits = logits[: len(_SPECIES_PROMPTS)]
        species_scores = scores[: len(_SPECIES_PROMPTS)]
        nonanimal_scores = scores[len(_SPECIES_PROMPTS):]

        best_idx = int(species_logits.argmax())
        best_logit = float(species_logits[best_idx])          # ← 게이트 ② 원본 점수
        animal_presence = float(species_scores.sum())          # ← 게이트 ① "동물 같음" 합
        nonanimal_presence = float(nonanimal_scores.sum())      # ← 게이트 ① "비동물 같음" 합
        second_logit = float(sorted(species_logits.tolist())[-2])
        species_gap = best_logit - second_logit                 # ← 게이트 ③ 1등-2등 차이

        if (
            best_logit < _ANIMAL_LOGIT_THRESHOLD          # 게이트 ②
            or animal_presence <= nonanimal_presence        # 게이트 ①
            or species_gap < _ANIMAL_SPECIES_GAP_THRESHOLD   # 게이트 ③
        ):
            return None

        if not _passes_size_gate(image):                    # 게이트 ④ (아래 함수)
            return None
        return _SPECIES_LABELS[best_idx]
    except Exception as e:
        print(f"[ERROR] Failed to predict animal: {type(e).__name__}: {e}")
        return None

def _passes_size_gate(image) -> bool:
    # 감지기 자체가 실패하면(모델 로드 불가 등)
    # 태그를 함부로 없애지 않도록 안전하게 통과시킴
    try:
        h, w = image.shape[:2]
        rgb = cv2.cvtColor(image, cv2.COLOR_BGR2RGB)
        mp_image = mp.Image(image_format=mp.ImageFormat.SRGB, data=rgb)
        result = _get_object_detector().detect(mp_image)

        best_ratio = 0.0
        for detection in result.detections:
            if detection.categories[0].category_name \
               in _ANIMAL_COCO_CATEGORIES:
                box = detection.bounding_box
                best_ratio = max(best_ratio,
                    (box.width * box.height) / (w * h))
        return best_ratio >= _MIN_ANIMAL_AREA_RATIO
    except Exception as e:
        print(f"[ERROR] Failed to run animal size gate: {type(e).__name__}: {e}")
        return True

STEP 05 · 되돌리기

장르 재확인

동물이 감지됐는데 사람 얼굴이 없으면 장르를 다시 "기타"로 되돌립니다. 여기서 face_count == 0 조건이 핵심입니다 — 진짜 사람 얼굴이 같이 찍혔다면(반려동물과 함께 찍힌 사진처럼) "인물" 판정은 근거가 있으니 되돌리지 않습니다. 인물이 아닌 다른 장르(음식·자연·사물·도시)는 애초에 얼굴 검출 경로를 안 거쳐서 face_count가 항상 0이니, 이 조건은 사실상 "인물" 오분류를 가려낼 때만 작동합니다.

이 규칙이 나온 계기는 실제로 오탐 두 번이었습니다. 처음 발견한 건 "인물" 오분류였습니다. 장르 판단 AI가 "인물"이라는 감각을 배운 사진이 거의 다 사람 얼굴 클로즈업(정면 응시, 큰 눈, 얼굴 중심 구도)이다 보니, 똑같은 구도의 고양이 클로즈업을 사람으로 착각했습니다 — 실측으로 96.6% 확신도까지 나왔습니다.

그런데 바로 다음 날 "동물 → 음식" 오분류도 나왔습니다. 의자 위에 앉은 고양이 사진이 62% 확신도로 "음식"이라고 나온 겁니다. 그래서 "인물"만 따로 고치는 대신, 동물 태그가 붙으면 원래 장르가 뭐였든 전부 보정하도록 범위를 넓혔습니다.

그럼 "동물"을 아예 새로운 장르로 만들면 되지 않았을까 싶은데, 장르 확률(genre_probs)이 5개 장르 그대로라 근거 없는 장르를 하나 더 끼워 넣으면 화면에 보여주는 확률과 안 맞습니다. 이미 #고양이 같은 동물 태그가 "무엇인지"를 알려주고 있으니, #기타 #고양이 조합만으로 충분하다고 판단했습니다.

카메라 시계 오류 보정 & 폐기된 3중 다수결

카메라가 시간대를 모를 때 남기는 기본값(+00:00)과 실제 시간대(예: +08:00)가 같이 저장돼 있으면, 그 차이만큼 촬영 시각을 자동 보정합니다. 실측 26장 중 12장이 이 패턴이었고, 보정 후 전부 실제 촬영 상황(맑은 대낮 등)과 맞아떨어졌습니다.

가장 흥미로운 설계 결정은 따로 있습니다. 처음엔 EXIF + CLIP + 밝기 휴리스틱, 셋을 투표시키는 3중 다수결을 시도했다가 되돌렸습니다. 그림자 짙은 대낮 숲 사진 250장 중 47%에서 CLIP과 밝기 판단이 동시에 야간으로 틀렸습니다. 둘 다 "어두우면 밤"이라는 같은 가정에 기대고 있어서 독립적이지 않았던 겁니다. 그래서 다수결을 하면 오히려 정확한 EXIF가 2대1로 밀렸습니다.

STEP 08 · OpenCV, AI 아님
opencv/feature_analyzer.py

특징 분석

여기서부터는 AI가 아닌 전통적인 이미지 처리입니다. 밝기는 픽셀 밝기 값의 중앙값(50백분위수)으로, 채도는 75 백분위수로 판단합니다. 평균 대신 백분위수를 쓰는 이유는, 사진 한쪽 구석에 아주 밝거나 채도 높은 부분이 있어도 극단값 하나에 전체가 휘둘리지 않게 하기 위해서입니다.

색 온도(따뜻한/차가운)는 색상 히스토그램으로 판단합니다 — 빨강 채널과 파랑 채널 각각의 "가중 평균 밝기"를 구해서, 빨강 쪽이 더 밝게 몰려있으면 "따뜻한", 파랑 쪽이면 "차가운"으로 봅니다.

흑백 판별이 의외로 까다로웠습니다. 사진 전체 평균만 보면, 국소적으로 색이 있어도(예: 금속에 반사된 색이 전체 픽셀의 4.7%만 차지) 나머지 무채색 영역에 희석돼 흑백으로 오판했습니다. 반대로 "색 픽셀이 조금이라도 있으면 컬러"로 하면 JPEG 압축 노이즈만으로도 진짜 흑백 사진이 컬러로 오판됩니다. 그래서 픽셀별 채널 표준편차가 8을 넘는 픽셀의 비율이 2% 이상이면 컬러로 보는 절충안을 씁니다 — 컬러 사진 30장, 흑백을 JPEG로 재인코딩한 사진 30장으로 실측해보니 이 기준으로 깨끗하게 갈렸습니다.

opencv/feature_analyzer.py 
def is_bw_image(image, pixel_threshold=8.0,
                 color_pixel_ratio=0.02):
    # 픽셀별 B/G/R 채널 표준편차
    per_pixel_std = np.std(
        image.astype("float32"), axis=2)
    ratio = float(np.mean(
        per_pixel_std > pixel_threshold))
    return ratio < color_pixel_ratio

def analyze_features(image):
    hsv = cv2.cvtColor(image, cv2.COLOR_BGR2HSV)
    gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)

    brightness = float(np.percentile(gray, 50))

    hist_b = cv2.calcHist([image], [0], None, [256], [0,256]).flatten()
    hist_r = cv2.calcHist([image], [2], None, [256], [0,256]).flatten()
    red_weight = np.sum(hist_r * np.arange(256)) / np.sum(hist_r)
    blue_weight = np.sum(hist_b * np.arange(256)) / np.sum(hist_b)
    color_tone = "따뜻한" if red_weight >= blue_weight else "차가운"

    saturation = float(np.percentile(hsv[:,:,1], 75))
    is_bw = is_bw_image(image)
    return {"brightness": brightness, "color_tone": color_tone,
            "saturation": saturation, "is_bw": is_bw}
STEP 09 · Average Hash
hash/average_hash.py

사진 지문 & 중복 감지

Average Hash는 사진을 8×8 픽셀(64개)로 확 줄여서, 각 픽셀이 전체 평균보다 밝은지 어두운지만 0/1로 기록하는 방법입니다. 결과물은 64자리 이진수 하나 — 사진의 "밝기 패턴 지문"인 셈입니다. 원본 사진의 색이나 세부 디테일은 다 날아가지만, 대략적인 명암 배치는 남아서 같은 사진을 다시 올렸을 때 지문이 똑같이 나옵니다.

지금은 이 지문이 완전히 똑같은 경우만 중복으로 판정합니다. 두 지문이 몇 비트나 다른지 재는 해밍 거리(Hamming distance) 계산 함수도 코드에 있지만, 지금은 완전 일치 검사에만 쓰고 있습니다 — 살짝 재인코딩된 사진까지 잡으려면 이 거리 비교를 실제로 활용해야 하는데, 이건 "부족한 점" 파트에서 다시 다룹니다.

중복이 확인되면 파일을 지우고 여기서 이 사진의 처리는 끝납니다 — 뒤에 나오는 임베딩 추출도, 태그 생성도, DB 저장도 건너뜁니다.

hash/average_hash.py 
def create_average_hash(image, hash_size=8):
    gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
    resized = cv2.resize(gray, (hash_size, hash_size),
                          interpolation=cv2.INTER_AREA)
    avg = float(np.mean(resized))
    bits = resized >= avg          # 평균보다 밝은 픽셀 = 1
    return "".join(
        "1" if bit else "0" for bit in bits.flatten())

def hamming_distance(hash_a, hash_b):
    # 두 해시가 몇 비트나 다른지 — 지금은 사용 안 함
    return sum(
        c1 != c2 for c1, c2 in zip(hash_a, hash_b))

ai/embedding.py

임베딩 추출

사진을 숫자 목록(1280차원 NumPy 벡터)으로 바꿔서, 비슷한 사진일수록 벡터도 비슷해지는 성질을 유사 사진 검색에 씁니다. 여기 쓰는 MobileNetV2는 분류기로 안 쓰고 특징 추출기로만 씁니다 — 분류 헤드를 떼어내고(include_top=False), 그 직전의 풀링된 특징만 꺼내는 겁니다.

그런데 얼굴/동물 검출에 이미 쓰고 있는 mediapipe로 이 유사도 벡터도 뽑으면 안 될까 싶을 텐데, mediapipe의 두 모델은 "탐지기"라서 정해진 결과(얼굴 여부, COCO 90종 중 뭐)만 내놓을 뿐 사진 전체의 유사도 벡터를 뽑는 기능 자체가 없습니다. 실제로 예전엔 자체 학습시킨 장르 분류 CNN의 레이어를 재활용해서 유사도 검색을 시도했었는데, 그 모델이 "5개 장르 구분"에 파인튜닝돼 있다 보니 같은 장르 안에서는 시각적으로 전혀 달라도 코사인 유사도가 전부 0.9 이상으로 뭉개졌습니다 — 유사도 검색이 사실상 "같은 장르인가"로 수렴해버린 겁니다.

그래서 어떤 작업에도 파인튜닝되지 않은, 순수 ImageNet 사전학습 MobileNetV2를 씁니다. 특정 과제에 치우치지 않았기 때문에, 오히려 "일반적인 시각적 유사성"을 더 잘 담아냅니다.

ai/embedding.py 
extractor = MobileNetV2(
    weights="imagenet",
    include_top=False,     # 분류 헤드 제거
    pooling="avg",          # 특징만 풀링해서 꺼냄
    input_shape=(224, 224, 3),
)

def extract_features(image):
    rgb = cv2.cvtColor(image, cv2.COLOR_BGR2RGB)
    resized = cv2.resize(rgb, (224, 224)).astype("float32")
    batch = preprocess_input(          # -1~1 정규화
        np.expand_dims(resized, axis=0))
    features = extractor.predict(batch)[0]   # 1280차원

    # L2 정규화 — 벡터 길이를 1로 맞춰서
    # 코사인 유사도 계산을 단순화
    features = features / (np.linalg.norm(features) + 1e-8)
    return features.astype(np.float32)

ai/tagging.py

태그 생성 & 저장

지금까지 나온 AI 판단 결과를 이 함수 하나로 모아 태그를 만듭니다. AI 모델이 바뀌어도 태그 규칙은 그대로 두면 되고, 업로드 기능과 재분류 스크립트가 이 함수 하나를 같이 씁니다.

세부 조건들도 다 이유가 있습니다. daynight가 None이면(흑백 사진처럼 판별 자체를 건너뛴 경우) 주간/야간 태그를 아예 안 붙입니다 — 모르는 걸 억지로 표시하지 않는 겁니다. indoor는 "실내"일 때만 태그를 붙이는데, "실외"는 이미 자연·도시 장르 태그가 그 정보를 담고 있어서 중복이기 때문입니다. 흑백 사진은 색 정보 자체가 없으니 color_tone(따뜻한/차가운) 태그도 붙이지 않습니다.

ai/tagging.py 
def generate_tags(genre, daynight,
    is_bw=False, indoor=None,
    color_tone=None, animal=None):

    tags = set()
    tags.update(genre_map.get(genre, []))

    if daynight is not None:
        tags.add(f"#{daynight}")
        if genre in ("도시","자연") \
           and daynight == "야간":
            tags.add("#야경")

    if is_bw:
        tags.add("#흑백")
    elif color_tone is not None:
        tags.add(f"#{color_tone}")

    if indoor == "실내":
        tags.add("#실내")
    if animal is not None:
        tags.add(f"#{animal}")

    return sorted(tags)

Self-review

부족한 점 및 개선 가능한 점

발표를 준비하며 코드를 다시 훑어보다 스스로 찾은 아쉬운 지점입니다.

01

CNN 학습 전처리 미비

CLIP으로 넘어온 뒤 다른 프로젝트의 학습 코드와 비교해보다가, 제 CNN 학습 파이프라인에 기본 전처리 두 가지가 빠져 있었다는 걸 알게 됐습니다. 첫째는 종횡비 문제입니다 — target_size=(224,224)가 원본 비율을 무시하고 정사각형으로 눌러버려서, 비율을 유지하며 가운데를 잘라내는 센터크롭 없이 사진이 찌그러진 채로 학습됐습니다. 둘째는 더 근본적입니다 — ImageNet 사전학습 가중치를 쓰면서 정작 정규화는 그에 맞는 preprocess_input(-1~1 범위)이 아니라 단순 rescale=1./255(0~1 범위)를 썼습니다.

02

중복 업로드 검사 순서가 비효율적

app.py의 업로드 처리는 얼굴 검출·장르·동물·낮/밤·실내외까지 무거운 AI 추론 5번을 전부 끝낸 뒤에야 사진 지문(Average Hash)을 만들어 중복을 확인합니다. 그런데 중복 검사에 필요한 건 이미지 로드 직후 계산 가능한 해시 하나뿐이라, 그 앞의 AI 추론 5번과는 아무 상관이 없습니다.

중복 사진을 올려도 결과적으로는 정확히 걸러내지만, 그 전에 불필요한 AI 연산을 다 하고 나서야 버려지는 낭비가 있습니다. 기능이 잘못된 건 아니고, 기능을 하나씩 순서대로 추가하다 보니 "일찍 걸러낼 수 있는 검사를 먼저 하자"는 순서 최적화를 놓친 경우입니다 — 해시 계산과 중복 검사를 이미지 로드 직후로 옮기면 간단히 고쳐집니다.
03

Average Hash가 완전 일치만 검사

find_duplicate_by_hash()가 해시를 정확히 일치하는 것만 검사합니다. Average Hash는 원래 약간의 차이(재압축, 리사이즈)까지 허용하려고 쓰는 방식이라, 해밍 거리(두 해시가 몇 비트나 다른지)가 어느 정도 이내면 중복으로 보는 게 원래 목적에 더 맞습니다. hash/average_hash.py에 해밍 거리 계산 함수(hamming_distance)까지 이미 만들어뒀는데, 정작 중복 검사에는 안 쓰고 있습니다.

지금은 완전히 똑같은 파일을 재업로드한 경우만 잡아냅니다 — 다른 방식으로 살짝 재인코딩되거나 리사이즈된 같은 사진은 중복으로 못 잡을 수 있습니다.
04

장르 CLIP 실패 시 안전장치 건너뜀

genre_predict.py의 predict_genre()는 CLIP 호출이 예외를 던지면 색상 기반의 약한 대체 로직(_heuristic_predict)으로 폴백하는데, 이때 "확신도 60% 미만이면 기타로 보낸다"는 안전장치를 건너뛰고 바로 결과를 반환합니다.

정리하면 이 네 가지는 "고장"이 아니라 "더 다듬을 수 있는 지점"입니다. 발표 자료를 준비하면서 코드를 다시 들여다본 게 오히려 이런 지점들을 스스로 발견하는 계기가 됐습니다.

Takeaways

마무리

01

AI 하나만 그대로 믿지 않는다

CLIP은 뭐가 됐든 "그나마 제일 그럴듯한 답"을 1등으로 뽑아버리는 성질이 있습니다 — 장미 사진이 "마카오앵무" 41%로, 커피잔이 "새" 96%로 나온 게 그 증거입니다. 그래서 동물 판별에서는 확신 점수(23.0)·1등-2등 점수 차이(2.5)·화면 대비 크기(1%)라는 서로 다른 성질의 신호를 4겹으로 겹쳐서 검증했고, 얼굴 검출은 mediapipe와 CLIP 두 모델을 이중으로 확인시켰습니다.

02

교차검증 방법은 서로 독립적이어야 한다

비슷한 방식끼리 다수결을 하면 오히려 맞는 답을 틀린 답이 이길 수 있다는 걸 실측으로 확인했습니다. EXIF + CLIP + 밝기 휴리스틱 3중 다수결을 시도했을 때, 그림자 짙은 대낮 숲 사진 250장 중 47%에서 CLIP과 밝기 판단이 동시에 틀렸습니다 — 둘 다 "어두우면 밤"이라는 같은 가정에 기대고 있어서 사실상 하나의 신호나 마찬가지였던 겁니다. 그 결과 다수결이 정확했던 EXIF를 2:1로 뒤집어버렸고, 지금의 "경계 근처에서만 좁게 재확인"하는 방식으로 되돌렸습니다.

03

버그는 실제로 써봐야 나온다

오늘 보여드린 안전장치는 전부 검증 스크립트가 아니라, 82장의 실제 사진을 직접 서버에 업로드해보며 발견한 것들입니다. 화재경보기 벨을 얼굴로 착각한 것도, 모나리자 포스터가 반복 인쇄된 매대 사진이 "인물"로 잘못 잡힌 것도, 미리 준비한 테스트 데이터셋이 아니라 실제로 써보는 과정에서 우연히 걸린 사례들이었습니다.
