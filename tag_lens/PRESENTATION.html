Concept

CLIP이란? — 사진과 문장을 함께 이해하는 AI

사진 한 장과 문장 여러 개를 같이 넣으면, 사진이 어느 문장과 가장 잘 어울리는지 점수로 알려주는 모델입니다.

인터넷의 수억 장 "사진+설명" 쌍으로 미리 학습되어 있어서, 우리가 카테고리를 새로 가르칠 필요 없이 문장만 바꾸면 즉시 새 기준으로 판단할 수 있습니다.

이걸 제로샷(zero-shot)이라 부릅니다 — 한 번도 직접 훈련시키지 않은 작업도 바로 할 수 있다는 뜻입니다.

이 프로젝트의 모든 분류 작업(장르 · 동물 · 주야간 · 실내외)이 이 방식으로 동작합니다.

예시 — 장르 판단

"a photo of nature landscape" 12%
"a photo of a city street" 78%
"a photo of food" 6%

→ 가장 높은 점수의 문장을 정답으로 채택 (78% ≥ 60% 임계값 → "도시" 확정)

장르 분류: CLIP 5-class 제로샷

얼굴이 있으면 바로 "인물" 확정. 없으면 CLIP에게 문장들을 주고 가장 잘 맞는 걸 고르게 합니다.

확신도가 60% 미만이면 억지로 고르지 않고 "기타"로 분류합니다 — 모르겠으면 모른다고 하는 게 더 정직한 결과입니다.

장르 보정: 동물 감지 결과로 되돌리기

동물이 감지됐는데 얼굴이 없으면 장르를 다시 "기타"로 되돌립니다.

장르 분류 AI가 "사람 얼굴 클로즈업" 학습 감각을 갖고 있어서, 고양이 얼굴 클로즈업을 사람으로 착각하는 경우(실측: 96.6% 확신도로 "인물" 오판)가 있었습니다.

face_count == 0 조건이 핵심 — 진짜 사람 얼굴이 검출됐다면(반려동물과 함께 찍은 사진 등) "인물" 판정은 근거가 있으니 보정하지 않습니다.

ai/genre_predict.py 
def resolve_genre_with_animal(
    genre: str,
    animal: str | None,
    face_count: int
) -> str:
    if (
        genre != "기타"
        and face_count == 0
        and animal is not None
    ):
        return "기타"
    return genre

주야간 판별: EXIF가 CLIP보다 우선

EXIF는 사진 파일에 같이 저장되는 보이지 않는 메타데이터입니다 — 촬영 시각, 카메라 기종 같은 정보가 들어있습니다.

픽셀이 밝은지 AI로 추측하는 것보다, 사진에 이미 기록된 실제 촬영 시각을 읽는 게 훨씬 정확합니다.

EXIF가 있으면 그 시각이 06~18시 사이인지만 보고 바로 확정하고, EXIF가 없을 때만 CLIP 제로샷으로 대체합니다.

태그 생성: 순수 로직, AI 아님

지금까지 나온 모든 AI 판단 결과를 이 함수 하나로 모아서 태그를 만듭니다.

AI 모델이 바뀌어도 태그 생성 규칙은 안 바뀌고, 업로드 경로와 재분류 스크립트가 이 함수 하나를 공유합니다.

결과는 SQLite의 photo / tag / photo_tag 3개 테이블(Many-to-Many)에 저장됩니다.

ai/tagging.py 
def generate_tags(genre, daynight,
    is_bw=False, indoor=None,
    color_tone=None, animal=None):

    tags = set()
    tags.update(genre_map.get(genre, []))

    if daynight is not None:
        tags.add(f"#{daynight}")
        if genre in ("도시","자연") \
           and daynight == "야간":
            tags.add("#야경")

    if is_bw:
        tags.add("#흑백")
    elif color_tone is not None:
        tags.add(f"#{color_tone}")

    if indoor == "실내":
        tags.add("#실내")
    if animal is not None:
        tags.add(f"#{animal}")

    return sorted(tags)

동물 판별: 왜 게이트가 4개나 필요했나

각 단계는 "이전 단계를 통과한 새로운 오탐"을 막기 위해 순서대로 추가됐습니다.

01

상대 비교 — 동물 vs 비동물

softmax로 "동물이 비동물보다 그럴듯한가" 비교

실패 사례: 커피잔 사진이 "새" 96%로 오탐 (약한 신호가 상대 비교에서 부풀려짐)
02

절대 로짓 임계값 — 23.0

softmax 전 원본 유사도 점수가 절대적으로 강해야 함

근거: 정탐 최고 로짓 24~28점대 / 오탐은 21점 이하
03

종(species) 로짓 gap — 2.5

1등 종과 2등 종의 점수 차이가 커야 함

근거: 정탐 gap 3.68~5.68 / 오탐(야경 반사 등) gap 0.80~1.56
04

화면 대비 크기 게이트 — 1%

mediapipe Object Detector로 실제 바운딩박스 면적 측정

근거: 점만 한 새 0.047% vs 확실한 동물 4.4%+ (165배 격차)

카메라가 시간대를 모를 때 흔히 남기는 기본값(+00:00)과 실제 시간대가 같이 있으면, 그 차이만큼 자동 보정합니다.

Takeaways

마무리

01

단일 모델의 판단을 그대로 믿지 않는다

CLIP도 뭔가는 항상 1등으로 뽑는 구조라, 로짓 절대값·gap·크기 같은 서로 다른 성질의 신호를 겹쳐서 검증했습니다.

02

교차검증 신호는 독립적이어야 한다

같은 종류의 신호끼리 다수결을 하면 오히려 정답을 뒤집을 수 있다는 걸 실측으로 확인했습니다.

03

버그는 실사용에서 나온다

오늘 보여드린 모든 방어 로직이 검증 스크립트가 아니라 실제 사진을 업로드해보며 발견한 것들입니다.

Q&A 대비

Q. 동물 판별 게이트를 왜 4개나 겹쳤나요?
각 게이트가 서로 다른 실패 유형을 막습니다 — 순서대로 하나씩 추가한 이유가 "이전 방어를 통과한 새로운 오탐이 계속 나왔기 때문"입니다.
Q. EXIF SubIFD 문제는 정확히 뭔가요?
getexif()는 IFD0만 반환하므로, 중첩된 Exif SubIFD를 get_ifd(IFD.Exif)로 따로 열어야 실제 촬영 시각을 얻을 수 있습니다.
Q. 3중 다수결을 왜 포기했나요?
픽셀 밝기 기반 신호 두 개가 서로 독립적이지 않아, 동시에 오판하는 경우 다수결이 정답(EXIF)을 뒤집었기 때문입니다.
Q. 재학습 없이 정확도는 어떻게 확보하나요?
실사용 사진 82장 전수 테스트로 오분류를 찾아, 프롬프트 문장이나 임계값/gap 후처리 로직으로 보완합니다.
Q. 배포/실서비스 확장이 가능한가요?
현재는 로컬 Flask 개발 서버 기준(CPU, ~3GB 메모리). 실서비스 확장 시 모델 서빙 최적화(양자화, GPU)가 필요합니다.
